### 1. 총평 (Overall Assessment)

이 프로젝트는 **책 추천 및 관리**를 위한 모바일 애플리케이션으로, React Native와 Expo 프레임워크를 기반으로 매우 체계적으로 구축되었습니다. 전반적으로 모던 웹/앱 개발의 좋은 관행들이 잘 적용되어 있으며, 코드의 재사용성, 유지보수성, 확장성을 모두 고려한 우수한 아키텍처를 가지고 있습니다.

- **목적**: 사용자가 책을 검색하고, 자신의 서재에 추가하며, 추천을 받고, 챗봇과 상호작용할 수 있는 기능을 제공합니다.
- **강점**: 컴포넌트 기반 아키텍처, 중앙 집중식 상태 관리, 명확한 관심사 분리, 타입스크립트를 통한 안정성 확보가 돋보입니다.

### 2. 주요 기술 스택 및 라이브러리 (Why this stack?)

프로젝트의 `package.json`을 분석한 결과, 다음과 같은 핵심 라이브러리들이 사용되었으며 선택 이유는 명확합니다.

- **`react-native` & `expo`**:
  - **이유**: 단일 코드베이스(JavaScript/TypeScript)로 iOS, Android, 웹 앱을 동시에 개발하기 위한 최상의 선택입니다. Expo는 네이티브 모듈 설정, 빌드 및 배포 과정을 크게 단순화하여 개발 생산성을 극대화합니다.

- **`expo-router`**:
  - **이유**: 파일 시스템 기반의 라우팅 라이브러리입니다. `app` 디렉터리에 파일을 생성하면 해당 경로가 자동으로 URL 및 화면으로 매핑됩니다. 이는 직관적이고 코드 기반 설정보다 훨씬 간편하여 내비게이션 구조를 쉽게 파악하고 관리할 수 있게 합니다.

- **`axios`**:
  - **이유**: HTTP 통신을 위한 라이브러리입니다. 특히 이 프로젝트에서는 `api/index.ts`에서 **인터셉터(interceptor)**를 설정하여 모든 API 요청에 자동으로 인증 토큰(JWT)을 헤더에 추가하는 로직을 구현했습니다. 이로 인해 각 API 요청 함수마다 인증 처리를 반복할 필요가 없어 코드 중복이 사라지고 유지보수가 용이해집니다.

- **`typescript`**:
  - **이유**: 정적 타입을 지원하여 컴파일 단계에서 오류를 미리 잡을 수 있습니다. 코드의 안정성과 가독성을 높이고, 대규모 프로젝트에서 협업 시 발생할 수 있는 실수를 줄여줍니다.

- **`@tanstack/react-query`** (또는 유사한 데이터 페칭 라이브러리 - 현재는 Context API 기반으로 구현됨):
  - **만약 사용했다면**: 서버 상태(API 데이터) 관리에 특화되어 로딩, 에러 상태 처리, 캐싱, 데이터 동기화 등을 매우 효율적으로 처리할 수 있습니다. 현재는 `BookContext`에서 유사한 역할을 직접 구현하고 있습니다.

### 3. 프로젝트 구조 및 아키텍처 (How it's built?)

프로젝트는 **관심사 분리(Separation of Concerns)** 원칙에 따라 매우 깔끔하게 구성되어 있습니다.

- **`app/`**: **화면 및 내비게이션**
  - `expo-router`가 이 디렉터리의 구조를 읽어 앱의 내비게이션을 구성합니다.
  - `_layout.tsx`: 공통 레이아웃 역할을 합니다. 루트 `_layout.tsx`는 전체 앱의 폰트나 스플래시 화면, 글로벌 상태 제공자(`BookProvider`)를 설정합니다. `(tabs)/_layout.tsx`는 로그인 후 진입하는 메인 탭 바(홈, 챗봇, 검색, 내 서재, 프로필)를 정의합니다.
  - `(tabs)/`: 괄호로 묶인 폴더는 URL 경로에 영향을 주지 않으면서 관련된 화면들을 그룹화하는 역할을 합니다. 즉, 인증된 사용자가 접근하는 핵심 기능들이 모여있습니다.
  - `login.tsx`, `signup.tsx`: 인증 관련 화면들입니다.

- **`api/`**: **외부 통신**
  - 백엔드 서버 및 외부 API(Google Books)와의 모든 통신 로직이 여기에 모여있습니다.
  - `index.ts`: `axios` 인스턴스를 생성하고, 모든 요청에 인증 토큰을 붙여주는 인터셉터를 설정하는 핵심 파일입니다.
  - `auth.ts`, `library.ts` 등: 각 도메인(기능)별로 API 호출 함수들을 모듈화하여 관리합니다.

- **`components/`**: **재사용 가능한 UI 컴포넌트**
  - `BookItem.tsx`, `Button.tsx`, `Input.tsx` 등 앱 전반에서 재사용되는 모든 UI 조각들이 위치합니다. `ui/` 폴더를 두어 순수 UI 컴포넌트를 분리한 구조는 매우 좋은 설계입니다.
  - `BookItemSkeleton.tsx`: 데이터 로딩 시 사용자 경험을 향상시키기 위한 스켈레톤 UI입니다. 세심한 UX 고려가 돋보입니다.

- **`contexts/`**: **전역 상태 관리**
  - `BookContext.tsx`: 이 앱의 **핵심적인 상태 관리 허브**입니다. React의 Context API를 사용하여 사용자 정보, 서재 목록, 추천 도서 등 앱의 여러 곳에서 공유되어야 하는 데이터를 중앙에서 관리합니다. `useBooks`라는 커스텀 훅을 통해 어떤 컴포넌트에서든 이 데이터에 쉽게 접근할 수 있습니다.

### 4. 핵심 로직 및 동작 방식 (How it works?)

#### **A. 인증 흐름 (Authentication Flow)**

1.  **로그인**: `app/login.tsx`에서 사용자가 이메일, 비밀번호를 입력합니다.
2.  **API 요청**: `api/auth.ts`에 정의된 `login` 함수(내부적으로 `api.post('/auth/login')` 호출)를 실행합니다.
3.  **토큰 저장**: 로그인 성공 시, 서버로부터 받은 **JWT(JSON Web Token)**를 `expo-secure-store`를 사용해 안전하게 기기에 저장하고, 사용자 정보는 `AsyncStorage`에 저장합니다.
4.  **자동 인증**: 이후 `api/index.ts`의 `axios` 인터셉터가 모든 API 요청을 보낼 때마다 `SecureStore`에서 토큰을 꺼내 `Authorization: Bearer <token>` 헤더를 자동으로 추가해줍니다.
5.  **화면 전환**: 로그인이 완료되면 `router.replace`를 통해 메인 탭 화면 `/(tabs)/`로 이동시킵니다.

#### **B. 상태 관리 (`BookContext`)**

이 프로젝트의 상태 관리는 `BookContext.tsx`를 통해 매우 효율적으로 이루어집니다.

- **중앙 데이터 저장소**: `BookProvider`가 앱의 최상단을 감싸고 있어, 앱의 모든 컴포넌트는 `useBooks()` 훅을 통해 `user`, `library`, `recommendations` 등의 전역 데이터에 접근하고, `addToLibrary` 같은 함수를 호출하여 상태를 변경할 수 있습니다.
- **데이터 로딩 및 통합**: `loadLibraryData`와 같은 함수는 백엔드 API에서 사용자의 서재 정보를 가져온 뒤, 각 책의 상세 정보(이미지, 저자 등)가 부족하면 Google Books API(`api/googleBooks.ts`)를 추가로 호출하여 데이터를 조합합니다. 이처럼 복잡한 데이터 fetching 로직을 Context 내에 캡슐화하여 컴포넌트는 그저 `loadLibraryData()`만 호출하면 되도록 단순화했습니다.

#### **C. 도서 검색 (`BookSearch.tsx`)**

1.  **입력**: 사용자가 검색창(`Input` 컴포넌트)에 검색어를 입력합니다.
2.  **디바운싱(Debouncing)**: `utils/useDebounce.ts` 훅을 사용하여 사용자가 타이핑을 멈춘 후 일정 시간(예: 500ms)이 지나야만 검색 API를 호출합니다. 이는 불필요한 API 요청을 막아 성능을 최적화하는 중요한 기법입니다.
3.  **API 호출 및 로딩 상태**: `api/googleBooks.ts`의 `searchBooks` 함수를 호출하여 Google Books API에서 책을 검색합니다. 검색이 진행되는 동안 `BookItemSkeleton` 컴포넌트를 보여주어 사용자가 로딩 중임을 인지하게 합니다.
4.  **결과 표시**: 검색 결과를 `BookItem` 컴포넌트 리스트로 표시합니다.
5.  **상세 정보**: 특정 책을 선택하면 `BookDetailModal` 모달 창을 띄워 상세 정보를 보여줍니다.

### 5. 코드 스타일 및 설계 원칙 (Coding Principles)

- **명확한 관심사 분리 (SoC)**: 위에서 설명했듯이 화면(app), API(api), UI(components), 상태(contexts)의 역할이 명확하게 분리되어 있어 코드를 이해하고 수정하기 쉽습니다.
- **컴포넌트 기반 설계**: 모든 UI가 재사용 가능한 작은 컴포넌트 단위로 만들어져 있어 일관성 있는 UI를 유지하고 개발 속도를 높입니다.
- **훅(Hook) 기반 로직 재사용**: `useDebounce`나 `useBooks`와 같은 커스텀 훅을 만들어 로직을 재사용하고 컴포넌트 코드의 복잡도를 낮춥니다.
- **타입스크립트를 통한 안정성**: 모든 함수, 변수, props에 타입을 지정하여 버그를 사전에 방지하고 코드의 의도를 명확하게 전달합니다.
- **추상화**: API 호출 로직을 `api` 디렉터리에 추상화하여 컴포넌트가 '어떻게' 데이터를 가져오는지 알 필요 없이, 그저 '무엇을' 원하는지만 요청하면 되도록 설계했습니다.

### 6. 결론

이 프로젝트는 최신 React Native 개발의 모범 사례를 잘 따르고 있는 고품질 애플리케이션입니다. 체계적인 아키텍처와 깔끔한 코드 스타일은 향후 기능을 추가하거나 유지보수할 때 큰 이점이 될 것입니다. 평가에서도 이러한 기술적인 성숙도와 설계의 우수성을 강조하면 좋은 결과를 얻을 수 있을 것입니다.
